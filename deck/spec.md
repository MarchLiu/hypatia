## Deck 常量

- 页面：960 × 540 px，原点左上。
- 配色：
  - 背景页底 `#FAFBFD`；深色页底 `#16294D`（封面/章节页/收尾）
  - 主墨 `#1B2A41`；正文 `#3D4C66`；弱化 `#7A8AA3`
  - 主色 `#2F6BFF`；青绿强调 `#12B5A5`；暖金强调 `#F2A93B`
  - 卡片底 `#FFFFFF`；软底 `#EEF2F9`；描边 `#D9E1EF`
- 字体：`"PingFang SC","Noto Sans SC",sans-serif`。
  - 封面主标 56px；章节页编号 96px/标题 40px；页标题 34px；小节标 22px；正文 20px；注释 15px
- 版式基准：页边距 64px；页眉左上（章节标签 15px 竖线 + 文字），右上页码；页标题 34px 位于 y≈96；内容区 y≈150–500

### P16 提取原则 I
- 标题 `提取原则（上）`。

  - `对质量保守，对时机激进`：`拿不准宁可跳过——低质知识点是未来的噪声；但每几轮就扫一次窗口，提取点滑出窗口的回收代价远高于当场判断`；
  - `纠错链是金子`：`问题 → 错误答案 → 用户纠正 → 修正：记录了"为什么错"和"正确的路"，最难从文档重新获得`。

### P22 三类 Agent 三种机制
- 标题 `适配不同 Agent 的机制`。
- 三竖卡：
  - `每轮重构 system prompt` → `确定性注入：任务开始执行一次 JSE 查询，把相关高层摘要固定进上下文`；
  - `持续上下文、能自主调工具（harness / openclaw）` → `技能层检索：需要时自己发起，任务中途发现线索可补查`；
  - `被动响应、几乎无主动权` → `边界触发：新任务开启、用户显式提醒时外部注入`。
- 底注：`hypatia skill 的存在就是为了吸收这些差异——回忆的触发设计进每个 Agent 最顺手的机制里。`

### P23 显式写入与显式读取
- 标题 `两条不该等待自动机制的通道`。
- 左右双卡：
  - `显式写入`：`"把这份集群运维文档写到 hypatia 里"——材料现成、结构清晰，跳过窗口直接拆解入库。读书、读文档、导入规格说明走这条路；工作量大、周期长，适合长时 Agent`；
  - `显式读取`：`"读一下 hypatia，找关于运维的记忆"——把检索从"Agent 的判断"变成"用户的指令"。opencode 试图直接 ssh 时，一句话提醒即完成手动复位`。
- 底部：`成本是一句话，回报是整个知识库的重新在场。`
